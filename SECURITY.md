# Security policy

## v1.0.0 release-candidate boundary

Run on loopback (`127.0.0.1`) by default. Local authentication and case-level access controls exist, but this development service must not be exposed publicly. Non-loopback HTTPS/proxy deployment needs separate review. MySQL persistence uses explicit migrations through 007 and InnoDB. Passive domain DNS/RDAP/CT, IP PTR/network-RDAP/ASN and single-page web metadata collectors use the central framework and controlled client; the synthetic mock remains available. Optional active verification is disabled by default and requires independent exact-target authorization. Login throttling is bounded to ten attempts per source address per minute per process; shared proxy addresses share a bucket. Account recovery remains unimplemented.

Phase 13 adds local-script CSP for the console, frame denial, nosniff, no-referrer, restrictive permissions and no-store defaults while preserving report sandbox CSP. Inline styles remain allowed for graph presentation; no remote scripts are allowed. Secure cookies can be required explicitly for HTTPS. Production configuration rejects blank/placeholder database credentials, root DB accounts, insecure cookies and DEBUG logs. This flag is not a substitute for deployment review.

The portable launcher disables access logs by default. JSON logging redacts request query strings, common credential/cookie/CSRF forms and configured database secrets; it never intentionally logs request bodies. Redaction is not a guarantee against arbitrary unlabeled sensitive text. `.env`, private investigation output, local credentials and logs are excluded from the allowlisted candidate archive. Review archives and run an advisory-backed dependency audit before public release; local pip consistency and heuristic scans are not CVE/secret clearance. See docs/DEPENDENCY_AUDIT.md and docs/RELEASE_CHECKLIST.md.

Domain collectors accept domain targets only. Fixed provider requests expose the seed domain to the selected public provider when the operator explicitly collects. DNS uses six fixed DoH queries, RDAP uses validated IANA bootstrap services, and CT uses one bounded documented provider page with a 60-second host interval. Provider discovery and redirects receive the same SSRF/TLS guards as other requests. No arbitrary URL collection endpoint, wordlist, recursive discovery, direct UDP collector, AI invocation, or automatic target authorization exists. Providers are replaceable trusted adapters; replacing one requires code review.

HTTP 429/503 responses impose per-host backoff; request Accept values are fixed per operation. Web success responses require HTML/XHTML; JSON, plain text and HTML/XHTML are accepted for web error responses. Received provider failures retain raw evidence with safe status codes and do not project unvalidated facts. DNS/RDAP can retain validated earlier responses after a later request fails. Overall framework cancellation or unexpected persistence failures can roll back a run's evidence. Facts and their evidence-backed relationships commit together. Wildcard certificate names and provider errors must not be treated as proof of a live host or negative findings.

Passwords use Argon2id. Session tokens are random, stored only as SHA-256 hashes in MySQL, expire, and are revoked on logout. Authenticated writes require a session-specific CSRF header. Cookies use HttpOnly and SameSite=Strict; Secure is applied on HTTPS. The CLI is the only account-provisioning path and requires trusted local access. Administrators can access all cases, with explicit audit records. Viewers cannot mutate cases; investigators require ownership or membership. Membership changes require ownership or admin role.

## Secrets and logging

Phase 05 IP collectors use only public provider HTTPS destinations, never the seed IP as a transport destination. Nonpublic seed addresses are rejected before run creation/provider access, even when recorded scope allows passive work. IP RDAP bootstrap uses longest-prefix selection, guarded service URLs and seed-containing allocation checks. RIPE prefixes must contain the seed; holder metadata is accepted only for origin ASNs already observed. PTR names are observations, not authorization or ownership. No port scan, service probe, reputation submission, geolocation, recursive enrichment or AI collector tool exists. Related-domain reads are restricted to stored same-case evidence.

IP facts reuse existing canonical entities and evidence relationships under the central persistence lock. Raw provider failures and partial responses remain attributable without becoming negative findings. Reputation is explicitly unconfigured; no clean/malicious verdict is inferred. Independently disabled IP providers cannot execute. No new secret/key handling or migration is required.

Keep secrets in local environment variables or an ignored `.env`, never in source, fixtures, screenshots, reports, or Git history. JSON logging redacts configured database passwords and common credential formats, including exception text. Do not log request bodies, authorization headers, raw evidence, full settings, or database URLs. Redaction cannot recognize every possible secret.

## Collector network boundaries

The Phase 03 controlled client enforces HTTPS/443, public DNS answers and IP literals, pinned transport destinations, original-host verified TLS, redirect revalidation, total deadlines, bounded retries, per-host rates, streamed body limits, and fixed request headers. Local/private/link-local/reserved/multicast, metadata, IPv6 transition, unsupported-scheme, and credential-bearing destinations are denied. No private-network override is exposed. Compressed responses are rejected. Ambient proxies and cookies are not used.

Only trusted code enters the static registry; there is no user plugin upload, arbitrary collector import, unscoped outbound URL API, or AI collection tool. Shipped collectors receive the controlled client and an immutable target snapshot, with no database handle. Python plugins are not sandboxed against malicious developer code; review any future plugin for direct sockets/HTTP/subprocess/DB access before registration. Async plugin deadlines are cooperative; OS DNS calls cannot be force-killed but outstanding network workers are capped. Limits are process-local, intended for a single server worker.

Phase 06 permits one explicitly requested GET of a scoped public HTTPS URL, with only bounded, revalidated redirects. It never follows page links, loads subresources, executes JavaScript, submits forms, authenticates to the target, or performs exploit checks. HTTP-only recorded targets remain valid records but cannot collect. Binary/oversized responses are aborted; HTML bytes remain untrusted raw evidence and the UI renders extracted values as text. Redirect bodies are skipped. Selected response headers are individually bounded and exclude cookies. Missing security headers create evidence-linked informational observations only; applicability and equivalent protections require human review. Failed, rate-limited and partially parsed responses produce no missing-header findings. A 404/410 is one response observation, not proof of global absence. `SPECTRE_WEB_METADATA_ENABLED=false` disables execution after restart.

Excluded/archived targets cannot run. A viewer cannot collect. Case isolation applies to run and evidence reads and collection writes. Active scope metadata does not permit active plugins. Started/completed/failed/denied framework actions are audited with operator attribution; failure diagnostics are safe codes rather than exception text. Raw evidence is untrusted case data and must never become executable instructions. The synthetic mock is explicitly labeled, not real intelligence.

Migration 004 repairs WAMP's MyISAM default by converting SPECTRE tables to InnoDB and restoring foreign keys. Existing rows are checked for orphan relationships before DDL, not silently deleted. Do not downgrade this storage hardening or enable collection with nontransactional tables.

## Access and active assessment

Phase 09 generation is stored-evidence-only and uses six explicit informational missing-header rules from Phase 06. It validates raw hashes, complete HTTP 200 HTML metadata, collector/snapshot identity and normalized header agreement. Partial/unavailable/failed/negative data cannot create new absence findings. Historical support is retained when later data is unavailable or the header is observed present; those states are explicitly distinct and never silently close analyst workflow. Confidence is fixed observation-support strength, not severity or calibrated vulnerability probability. No AI participates.

Case-bound generation and analyst mutations require existing RBAC/CSRF. Generation skips archived/excluded targets and disallowed snapshots; archived cases cannot generate/edit. Findings reads join their target to the same case; entity and evidence/relationship support reads validate case ownership. Redirect support must match the stored Phase 07 deterministic plan. Foreign keys and unique target/rule identities preserve evidence references and replay safety. Overrides preserve the initial rule result, require a reason, and leave confidence unchanged. Revisions store case-authorized notes/reasons; audit metadata uses IDs and safe workflow fields, without raw provider payloads or analyst free text. Shared locks cover generation/updates and audit commit; failures roll back new records. No Phase 09 action invokes a collector or arbitrary network client.

Phase 08 graph/detail/timeline routes are read-only and case-authorized. They reuse Phase 07 supports and same-case evidence joins. UI filtering, focus, expansion and inspection use GET only; none starts correlation or collection. Raw JSON uses text nodes, never HTML injection. Case/detail generation guards discard stale responses; timeline request tokens prevent older pages replacing newer ones. Local Cytoscape assets avoid runtime third-party requests. Graph/rendering/event/evidence bounds disclose partial views. Existing mutations retain CSRF and auditing.

Phase 07 correlation imports no collector, network client or AI engine. Jobs read evidence only through a case-bound run/target join, validate raw evidence hashes and source/run/snapshot consistency, and use explicit normalized-observation rules. Unsupported/error data creates no derived links; malformed items are skipped with safe reasons. Current excluded/archived targets and disallowed collection snapshots cannot generate new links. Existing historical links remain readable by authorized case members. No derived entity receives target authorization automatically.

Jobs require case mutation access and CSRF; archived cases reject them. Results and failures are audited. Writes and outcome audit commit together under the existing persistence lock; failures roll back new entities/supports. Canonical uniqueness and foreign keys remain in force. Graph reads require case access and validate that evidence targets and both endpoint entities belong to the same case. Cross-case support rows are omitted rather than disclosed. Confidence is a documented rule constant, not probability of ownership or an AI judgment. Canonical organization labels do not identify verified legal entities. Bounded graphs explicitly report truncation; correlation jobs expose a continuation cursor. One-server-worker constraints remain.

Add case-level RBAC and audited access before collection. Keep active assessment disabled by default; require recorded authorization, an active-authorized target, explicit operator confirmation, strict rates, and a case kill switch before any active workflow. Prohibited features are defined in RESEARCH_SCOPE.md.

## Read-only AI boundary

AI is optional and disabled by default. Case authorization precedes retrieval and is rechecked after inference. The five application-controlled tools are `get_case_summary`, `search_entities`, `get_entity_evidence`, `list_findings` and `explain_relationship`. Their case ID is bound at construction; model input contains no database/session, tool executor, filesystem, shell, collector or general HTTP client. Evidence retrieval joins run/target ownership and validates raw SHA-256; relationship endpoints and supports and finding evidence are case-checked. Explicit record IDs and textual citations outside the prepared context are rejected without disclosing whether a record exists. Administrators retain the existing audited case access; authorized viewers may ask read-only questions. POST requires existing CSRF protection.

The provider can select only catalog fact IDs with their exact evidence IDs. Server-owned text/record links are rendered, never arbitrary model prose or URLs. Unknown/duplicate citations, extra fields, malformed schemas and model tool calls fail closed. Unknown questions receive insufficient-evidence responses; action/URL/credential requests are refused. Keyword checks are defense in depth; the real security boundary is the absence of capabilities and the strict output allowlist. Stored hostile text is bounded untrusted JSON data under a separate system policy, and UI rendering uses text nodes. Prompting alone is not relied upon to prevent actions or unsupported factual claims. Relevance selection can still be imperfect; the assistant is extractive, not independent verification.

The Ollama adapter is separate from the controlled collector client. Its only destinations are literal `127.0.0.1:11434/api/show` (model metadata only) and `/api/chat`. It rejects cloud names/remote metadata and requires local GGUF format before sending case text. Disable Ollama cloud features with `OLLAMA_NO_CLOUD=1`. No configurable URL, proxy, redirect, cloud credential or install/pull endpoint exists. A trusted local daemon and host remain prerequisites; the application cannot sandbox a malicious process already controlling the local endpoint. One concurrent inference, bounded context/response and deadlines prevent unbounded application-side output; underlying socket read timeouts are cooperative.

No conversations or AI output are saved. Previous AI answers never become context/evidence. Only usage audits are written by the assistant, excluding questions, answers, raw evidence and credentials. The question plus bounded case title/description and selected stored facts/support IDs are sent to local inference; raw provider bodies/contact records and analyst notes are excluded. No external AI provider is shipped. Replacing the adapter requires review of privacy and network guarantees. Disabled/missing/unavailable providers, timeouts, invalid context and citation failures leave core investigations available. AI cannot alter targets/scope, evidence, observations, entities, relationships, findings, severity/confidence, cases or audit contents, and cannot invoke collection. Phase 11 reports do not call AI.

## Report export boundary

Report preview and export authorize the case through existing ownership/membership/RBAC checks before building a context. Unrelated case IDs return 404; viewers may preview but cannot export. POST export requires the existing CSRF token. Finding target/entity/evidence/relationship supports are checked inside the same case; relationship support evidence must also appear in the finding's evidence links. Stored raw evidence hashes are recomputed and mismatches fail closed. Exports never rewrite investigation data, regenerate findings/correlation, or invoke collectors/AI. Historical archive/exclusion does not grant network authorization.

Reports use an explicit record-field allowlist, excluding raw provider bodies, account/session credentials, arbitrary entity attributes, AI text and audit metadata. Default analyst-text redaction omits case description, finding notes and override reasons. Configured database secrets, common credential assignments (including quoted JSON and encoded query keys), nested credential-key values, authorization tokens and URL userinfo are scrubbed. Redaction cannot identify arbitrary unlabeled secrets; names/targets/infrastructure remain visible. Review exports before sharing. If redaction would change a provenance hash, export is blocked instead of presenting a modified hash as verified.

HTML values are escaped; PDF paragraph markup is escaped. Navigation links use validated in-case numeric IDs and internal anchors, never provider/model URLs. No active scripts, external fonts/images, remote resources or HTML-to-browser PDF processing exists. Responses are attachments with fixed server-owned filenames, no-store/nosniff and a restrictive HTML sandbox CSP. The application renders in memory and accepts no filesystem path. Exported files remain sensitive independent copies and cannot be revoked by changing later case permissions.

Limits: 10,000 targets/runs/evidence/findings/selected audit rows per category, existing graph limits of 5,000 entities/10,000 support rows, 8 MiB serialized context and 20 MiB final output. Exceeding a limit blocks export rather than silently omitting records. Two concurrent exports per process are admitted; busy requests receive 429. Snapshot construction uses the existing central persistence lock and database transaction. This single-process local architecture is not a distributed export/locking service. Rendering errors are safe 503 responses, leaving core HTML/investigation functionality available; no exception payload/provider text is logged.

Success/failure audits record actor/case, timestamp, format and safe outcome metadata. Success also records report version, digest, redaction and byte count. Content excludes auth/export/admin-access audit events and generation wall-clock timestamps for reproducibility. Reporting requires no separate persisted report table. Phase 12 adds stored active history only to cases containing it; passive-only report snapshots and bytes remain unchanged.

## Optional active verification boundary

Phase 12 is a separate, disabled-by-default execution layer. A current authenticated session, existing RBAC/case membership, unarchived active-authorized target, exact-target owner/admin grant, unstopped case and confirmed action are all required server-side. Scope changes invalidate grants. Revocation and kill/cancel are checked between network steps and before committing positive observations. Viewer access is read-only. A discovered host/IP/SAN never inherits permission; no active modules are registered with the passive collector registry or exposed as AI tools.

Only GET/HEAD/OPTIONS and explicitly granted web ports 80/443 are supported. Every DNS answer must be public and connections are pinned to validated addresses with verified original-host TLS. Private/local/link-local/metadata addresses, mixed public/private answers, host-changing redirects and TLS downgrades are blocked. The existing passive HTTPS-only network client was not weakened. Active HTTP port 80 is an isolated explicit-grant capability, not a generic arbitrary-URL proxy.

Limits: one active run per process, two seconds between per-host starts, 20-second total deadline, five-second connection/read timeout, two redirects, 64 KiB uncompressed body and bounded headers. This local single-process service must not be scaled to multiple workers to bypass admission/rate limits. Cancellation cannot recall a request already sent; bounded OS calls can finish, but subsequent steps/positive commits are rejected. Background jobs are not durable/replayed automatically after restart.

Request bodies, cookies, credentials, arbitrary destination URLs and arbitrary custom headers are prohibited. The manual builder accepts only a specific validated path, small non-sensitive query parameters and Accept/Accept-Language. Query/header values are not persisted. Selected response metadata is scrubbed; arbitrary HTML is omitted; only bounded robots/security.txt plain text can be previewed. Secret redaction cannot detect arbitrary unlabeled secrets. Safe HTTP methods can still have application-specific side effects, so the investigator must choose a truly non-mutating path.

Active evidence has distinct source types and immutable hashes. Failures/partial/negative responses are separate states; failed verification never means a finding is false. Missing-header verification compares against the original case-local, hash-verified captured resource. Original findings and analyst severity/confidence remain unchanged. Informational active rules describe captured observations, not exploitability. Grant/revoke, request/start/outcome, evidence, manual execution and finding verification are audited without raw request secrets.

Reports include active history only when it exists, preserve evidence references and redact authorization notes by default. AI permissions/providers remain unchanged and disabled. No unrestricted scanning, exploitation, credential attacks, payload engine or Phase 13 work was added.

## Reporting a security issue

Until a private reporting channel is established, avoid publishing exploit details, credentials, or sensitive evidence in public issues. Report privately to the repository owner through an agreed channel. No automated reporting or external telemetry is configured.
